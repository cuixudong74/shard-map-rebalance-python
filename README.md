# shard-map-rebalance

分片映射（shard map）的版本化管理与在线再平衡服务。纯本地实现，不依赖外部
服务与真实凭据：节点存储由 `InMemoryBackend` 模拟，状态通过本地文件
（快照 + 日志）持久化，可在本机完整复现映射管理与迁移过程。

## 运行

```bash
uv sync
uv run python main.py            # 启动服务（SHARDMAP_WORKDIR 指定数据目录，默认 ./data）
uv run pytest                    # 运行全部自动化测试
```

## 映射版本语义

- 映射以**单调递增的整数版本**提交，`MapVersion` 不可变（`MappingProxyType` 冻结）。
- 提交是原子的：任意时刻读取方只能拿到某个**完整且已提交**的版本，写读并发
  时不会出现新旧归属混合（`store.commit` 要求版本号严格 +1，否则拒绝，
  原因码 `version_conflict`）。
- 读取方凭版本号判断是否需要刷新：`GET /map` 返回当前版本号，与本地缓存
  比对即可。
- 长事务读取方可 `pin(version)` 钉住版本；GC 不会回收仍被钉住的版本
  （见下文“内存与回收”）。

## 再平衡策略

- **确定性**：`planner.compute_plan` 先对节点与分片排序，所有决策（谁多拿一个
  分片、驱逐哪些分片、填充顺序）只依赖排序后的序列与分片/节点 id，与遍历
  顺序无关。同一输入与同一目标必得同一方案（含 `plan_id`，由输入指纹派生）。
- **最少迁移**：保留在存活节点上的分片不动；只为平衡计数而迁移，且每个分片
  至多迁移一次。目标计数为 `floor/ceil(n/k)`，多出的一个分片优先分给当前
  负载最高的节点（减少迁移），并列时按节点 id 字典序。
- **在线执行（copy-then-swap）**：执行器先把分片数据从源节点拷贝到目标节点
  （此间映射仍指向源，读写不中断），然后提交一个全新版本把该分片切到目标。
  读取方永远不会读到尚未完成迁移的部分。源数据仅在没有被钉住的旧版本
  引用时才删除。
- **慢节点隔离**：迁移由有界线程池并行执行（`max_parallel_shards`），单个慢
  节点最多占住一个 worker，其余分片照常迁移；单分片拷贝超过
  `shard_timeout_s` 记为失败，不影响其他分片。
- **取消/超时**：取消或分片失败只会让任务终止；已提交的每个版本都是自洽的，
  映射绝不停留在“半个版本”的中间状态。

## 分裂与合并

- 分裂：父分片先在新版本中标记 `SPLITTING`（仍为权威归属），数据按键的
  SHA-256 确定性分配到子分片，然后提交子分片为 `ACTIVE` 的版本，父分片消失。
- 合并：子分片标记 `MERGING`（仍为权威归属），数据汇入目标分片后提交目标
  分片为 `ACTIVE` 的版本。
- 路由策略（`splitmerge.route`）：迁移期间新到的请求路由到**当前权威归属**——
  分裂期间路由到父分片；合并期间路由到子分片（指名合并目标的请求确定性地
  路由到字典序最小的仍在权威状态的子分片）。任一时刻一个分片只有一个权威
  归属，分裂合并前后数据不丢不重（测试逐键校验）。

## 崩溃恢复

- 每次提交都把当前版本写入 `snapshot.json`（原子替换）；所有再平衡/分裂/
  合并事件追加到 `journal.jsonl`（fsync）。
- 重启后协调器从快照恢复映射，并扫描日志识别未完成的工作：
  - 未闭合的迁移任务：按 `recovery_policy` 处理——`abort`（默认，安全中止，
    映射停留在最近一个自洽版本）或 `resume`（继续剩余分片的迁移）。
  - 未闭合的分裂/合并：子分片/目标从未成为权威归属，直接回滚标记状态并
    清理半成品数据，映射回到自洽版本。
- 恢复是幂等的，重复调用不产生额外动作。

## 越权与配额

- `CallerPolicy` 按调用方限定可操作的分片集合（`allowed_shards`，`None` 表示
  不限）与并发操作数（`max_concurrent_ops`）。
- 所有检查发生在**任何映射变更之前**；拒绝原因可机器区分：
  `unauthorized_shard`、`concurrency_exceeded`、`version_conflict`、
  `invalid_plan`、`rebalance_in_progress`、`not_found`、`invalid_state`。
- 全部操作（含拒绝前的提交点）写入有界审计日志 `AuditLog`，可通过
  `GET /audit` 追溯。

## 内存与回收

- 历史版本保留数量有界（`max_retained_versions`），超出的旧版本由 GC 回收；
  被读取方钉住的版本豁免，释放后方可回收。
- 审计日志为固定容量环形缓冲；日志文件只追加，快照只保留当前版本，
  内存与磁盘占用均有界。

## 配置项

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `workdir` / `SHARDMAP_WORKDIR` | `./data` | 快照与日志目录 |
| `max_retained_versions` | 16 | 内存中保留的历史版本数 |
| `max_parallel_shards` | 4 | 并行迁移的分片数 |
| `shard_timeout_s` | 30.0 | 单分片拷贝超时（秒） |
| `recovery_policy` | `abort` | 重启后对未完成迁移的策略：`abort` / `resume` |
| `audit_capacity` | 1024 | 审计日志容量 |

## HTTP API 摘要

| 方法/路径 | 说明 |
| --- | --- |
| `POST /bootstrap` | 初始化映射（节点列表 + 分片数） |
| `GET /map`、`GET /map/{version}` | 读取当前/指定版本 |
| `GET /route/{shard_id}` | 按既定策略解析请求的权威分片与节点 |
| `POST /rebalance` | 计算并启动再平衡（目标节点集合） |
| `GET /rebalance` | 查询迁移进度（逐分片状态与字节数） |
| `POST /rebalance/cancel` | 取消进行中的再平衡 |
| `POST /split`、`POST /merge` | 分裂 / 合并 |
| `POST /recover` | 识别并按策略处理未完成的工作 |
| `POST /policies` | 设置调用方权限与配额 |
| `GET /audit` | 查询操作记录 |

## 测试覆盖

`tests/` 覆盖：并发读写版本一致性、版本钉住与 GC、再平衡确定性与最少迁移、
节点增减、在线迁移不中断读写、慢节点隔离、取消与超时、分裂合并的归属与
数据不变量、迁移中断与重启恢复（abort/resume）、快照回环、越权与配额、
审计追踪、HTTP 端到端流程。
